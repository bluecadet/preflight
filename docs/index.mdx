<Features>
  <Feature title="Check() before Apply()">
    Every built-in and plugin module answers `Check()` before `Apply()` runs. Dry runs call the same
    `Check()` code as a real apply.
  </Feature>
  <Feature title="Offline-capable staging">
    `stage` writes a per-target bundle: plan, manifest, plugins, and encrypted secrets. `apply --bundle`
    runs it on the target with no network.
  </Feature>
  <Feature title="Explicit phases">
    Fetch pins actions. Plan builds a DAG without touching targets. Stage writes the bundle. Only Apply
    changes a machine.
  </Feature>
</Features>

<GlyphList intro="Included in the binary.">
  <Fragment slot="title">
    Preflight's <em>key features</em>
  </Fragment>
  <GlyphItem glyph="✓" lead="One playbook, any delivery.">
    `apply` runs the same playbook locally, over SSH or WinRM, or from an offline bundle.
  </GlyphItem>
  <GlyphItem glyph="✓" lead="Select targets by host or group.">
    Variables merge from inventory to group to host, and one command runs across every selected
    host.
  </GlyphItem>
  <GlyphItem glyph="✓" lead="Facts and templating built in.">
    `{{ facts.os.arch }}` and `{{ target.name }}` resolve per target at run time, so one playbook
    covers every host.
  </GlyphItem>
  <GlyphItem glyph="✓" lead="Repo-backed, `age`-encrypted secrets.">
    Encrypted secrets live in the project repo and decrypt on the machine running `preflight`. No
    plaintext in YAML and no central vault.
  </GlyphItem>
  <GlyphItem glyph="✓" lead="Per-user settings without signing in.">
    `registry` and `environment` edit another user's profile hive, loading it on demand when that
    user is signed out.
  </GlyphItem>
  <GlyphItem glyph="✓" lead="A stdlib that ships with the binary.">
    Embedded actions such as `preflight/windows-machine` and `preflight/autologin` ship with each
    release and resolve before project-local actions.
  </GlyphItem>
</GlyphList>
