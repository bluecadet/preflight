<Features>
  <Feature title="Check() before Apply()">
    Every built-in and plugin module answers `Check()` before `Apply()` ever runs. Dry-run and real
    execution share one code path, not two.
  </Feature>
  <Feature title="Offline-capable staging">
    `stage` writes a per-target bundle: plan, manifest, plugins, secrets. `apply --bundle` converges
    a target with no network at all.
  </Feature>
  <Feature title="Explicit phases">
    Fetch pins actions. Plan builds a DAG without touching targets. Stage writes the bundle. Apply is
    the only phase that mutates anything.
  </Feature>
</Features>

<GlyphList intro="What Preflight handles out of the box.">
  <Fragment slot="title">
    Preflight's <em>Key Features</em>
  </Fragment>
  <GlyphItem glyph="✓" lead="Run the same path everywhere.">
    Local, remote, or staged-and-offline: `apply` converges the same playbook the same way.
  </GlyphItem>
  <GlyphItem glyph="✓" lead="Select targets by host, group, or tag.">
    Inventory variables cascade from inventory to group to host, and CLI commands fan out across a
    selector instead of one target at a time.
  </GlyphItem>
  <GlyphItem glyph="✓" lead="Facts and templating built in.">
    `{{ facts.os.arch }}`, `{{ target.name }}`, and friends resolve at plan time, so one playbook
    reads the same across every target.
  </GlyphItem>
  <GlyphItem glyph="✓" lead="Repo-backed, `age`-encrypted secrets.">
    Secret values travel with the project's config and decrypt only at apply time. No plaintext,
    no central vault.
  </GlyphItem>
  <GlyphItem glyph="✓" lead="Identity-aware execution.">
    `become` runs a task under a different user account when the outcome depends on whose
    registry keys or files get touched.
  </GlyphItem>
  <GlyphItem glyph="✓" lead="A stdlib that ships with the binary.">
    Embedded actions like `windows-machine` and `autologin` are versioned with the release and
    resolved before any project-local action.
  </GlyphItem>
</GlyphList>
